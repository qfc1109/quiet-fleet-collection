# ADR-001：项目级 RAG 知识库与文档问答

- 日期：2026-09-05
- 最近更新：2026-09-07
- 状态：产品约束已确认，技术实现尚未开始
- 关联文档：[需求分析](../requirements.md)、[设计文档](../design.md)、[开发文档](../development.md)、[术语表](../glossary.md)

## 1. 记录目的

本文记录项目级 RAG（检索增强生成）知识库和文档问答的共同决策，作为后续需求拆分、接口设计、数据迁移和验收的依据。文中“规划”“拟议”内容不代表当前系统已经提供对应能力。

## 2. 已核实的现状

- 产品名称是“轻帆集 / Quiet Fleet Collection”。
- 后端是 Java 8 + Spring Boot 2.7 + MyBatis-Plus，业务数据在 MySQL，文件正文在本地存储；当前没有 RAG、Embedding、向量库、全文检索或消息队列。
- 现有 `project` 和 `project_file` 可以作为初始项目范围，但没有项目成员、文件纳入标记、正文分块、哈希、索引状态或模型版本字段。
- 现有主站项目空间按 `project.owner_user_id` 限制，尚无项目成员关系；部分公开文件接口按 `fileId` 读取时没有统一重新校验项目可见性，问答和引用不能直接复用这条读取路径。
- 只读盘点发现公开项目文件名中包含 `id_rsa`、`.pem`、`.key`、配置和脚本等高风险类型。未读取文件内容，因此不能断言其一定是真实凭据，但在索引前必须按敏感资料处理。

## 3. 已确认决策

| 主题 | 决策 |
| --- | --- |
| 产品边界 | 轻帆集是产品边界；模型通过可配置的 OpenAI 兼容 REST 自定义适配器接入，`baseUrl`、模型名、API Key、超时和额度均配置化且密钥只放后端。当前确认模型名为 `gpt-5.6-terra`；具体服务地址和凭据在部署时提供。 |
| 知识库范围 | 一个项目对应一个逻辑知识库，使用 `project_id` 做隔离；不先创建多个物理向量库。 |
| 使用者 | 第一版面向项目内部成员，不开放匿名访客问答。 |
| 成员模型 | 新增项目级成员关系和 `VIEWER` / `EDITOR` 角色；两种成员都可以查询已纳入问答的文件；`VIEWER` 只读问答，`EDITOR` 可编辑项目文件；成员管理和外部共享仅负责人可操作；暂不做文件级 ACL。 |
| 无所有者项目 | 仅后台管理员可以为管理员创建的无所有者项目指定网站用户负责人；指定负责人前不能启用问答。 |
| 纳入策略 | 默认不自动入库；负责人显式勾选文件或目录，支持批量选择；目录选择只形成当前文件快照，新增文件必须再次显式选择；后端强制阻止密钥、数据库、压缩包等高风险文件。 |
| 首批解析格式 | MVP 只实现 Markdown、纯文本和 Word；PDF 后置，不能把浏览器预览当作文本抽取。 |
| 外部服务 | 只有负责人显式选中的非敏感资料可以发送到外部服务；页面必须明确数据去向；未选文件不能随请求外发。 |
| 回答依据 | 只根据检索到的资料回答；无依据时明确回复“资料中没有找到”，不以常识补全为事实。 |
| 更新策略 | 上传或修改后异步增量索引；删除和权限撤销立即从召回范围排除；失败文件可单独重试。 |
| 索引状态 | 文件状态至少为“待处理、索引中、可用、失败”；部分文件失败时仍允许使用可用文件，并提示知识库不完整。 |
| 聊天形态 | 页面内临时多轮，只携带最近三组问答；不保存聊天正文，不提供历史列表。 |
| 引用 | 响应返回 `fileId`、`relativePath`、`quote`、`locator`；支持点击打开原文。Markdown 优先定位行或标题，PDF 定位页码，Word 定位段落，无法精确定位时退化为打开文件。 |
| 响应 | 第一版使用普通 JSON；页面显示加载状态，聊天请求单独使用约 30 秒超时；流式输出后置。 |
| 规模 | 先按不超过 100 个项目、每项目 500 个可索引文件、同时 5 个问答设计；超过后依据监控迁移检索设施。 |
| MVP 反馈 | 每个回答返回临时 `answerId` 并提供“准确 / 不准确”判断；每个用户对同一回答只保留一次评价，反馈表只保存 `answerId`、`userId`、`vote`、`projectId`、`createdAt` 等统计元数据，不保存聊天正文。 |

## 4. 预期领域模型

以下是实现时的最小概念，不代表当前数据库已经存在对应表：

- `project`：逻辑知识库和权限根。
- `project_member`：项目成员、`VIEWER` / `EDITOR` 角色及有效状态。
- `knowledge_file`：项目文件是否纳入问答、敏感类型判定和当前索引状态。
- `knowledge_chunk`：抽取文本、分块顺序、来源文件和定位信息；Embedding 存储方式待定。
- `chat_feedback` 或等价统计记录：以临时 `answerId` 去重的准确性判断和必要的聚合维度，不保存聊天正文。

负责人拥有成员管理、纳入范围、外部数据共享和失败重试的控制权。`EDITOR` 可编辑项目文件；成员邀请/移除的具体交互和后台指定负责人的接口细节仍需在实现阶段落实。

## 5. 约束下的问答流程

1. 服务端按网站用户身份解析项目，并校验项目未删除、成员关系和角色。
2. 只取负责人已启用且状态为“可用”的文件；再次执行项目和权限过滤，不能只信任索引元数据。
3. 首期使用项目内简单文本/关键词召回，保留来源文件、相对路径和定位信息。
4. 若没有达到最低相关性，返回固定拒答，不输出无依据结论。
5. 若项目启用了外部服务，只发送负责人选中的非敏感片段、用户问题和必要的临时上下文。
6. 把回答和引用以普通 JSON 返回；用户可立即提交准确性判断。

文档内容是不可信输入。提示词必须把检索片段当作资料而非系统指令，禁止文档内容触发工具调用、越权读取或泄露未检索内容。

## 6. 明确不纳入本次 MVP

- 匿名访客问答。
- 文件级 ACL。
- 持久化聊天历史、历史列表和跨设备续聊。
- SSE/WebSocket 流式回答。
- 图片 OCR、复杂版式 DOCX、未验证的 PDF 全量抽取。
- 外部网盘、网页或数据库同步。
- 在没有容量和命中率证据前建设分布式向量平台。

## 7. 实现输入与工程待办

产品路线已在本轮闭环；以下是开始编码前需要落实的配置、安全处理和工程细节，不改变已确认的产品规则。

1. 提供自定义模型适配器的实际 `baseUrl`、API Key、超时和额度；模型名已确定为 `gpt-5.6-terra`。API Key 只通过被忽略的本地/部署配置注入，密钥不得提交到仓库。
2. 落实成员邀请和移除流程、后台管理员指定网站用户负责人的入口和校验；`VIEWER` / `EDITOR` 的问答与文件编辑边界，以及“仅后台管理员可指定负责人”的规则已确认。
3. 落实文件选择的持久化、敏感文件 denylist/内容检测、Markdown/纯文本/Word 抽取和编码策略；PDF 作为后置能力。
4. 将项目内简单文本/关键词召回作为 MVP 检索路线；是否引入 Embedding/托管知识库以后再由监控和反馈决定。
5. 落实 `answerId` 生成、反馈唯一约束、保留期和报表维度；“每用户每回答一次”及不保存聊天正文已确认，固定准确率门槛仍未确认。
6. 设计可重试的索引 worker/outbox 和手工数据库迁移；不能把外部模型调用绑定在上传 HTTP 事务内。
7. 在任何索引 worker 读取文件前，处理公开项目中的疑似密钥/配置文件；如确认是真实凭据，先撤下并轮换。

在上述前置项完成前，不得把当前公开项目的全部文件直接发送给外部模型，也不得宣称“每个项目已自动成为知识库”。
